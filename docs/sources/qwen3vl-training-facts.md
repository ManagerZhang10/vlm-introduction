# Qwen3-VL 训练事实 + 作者早先 14 天讲义（D01–D14）梳理

先说结论：报告把训练讲得很清楚（4 段预训练 + 3 段后训练，大量"用旧模型重写数据"），但没给结构设计的消融（DeepStack 除外），也没给 loss 公式。作者早先那套 14 天讲义（D01–D14）的实测**全部是 4B**，没有一条 8B 实测。

## 一、Qwen3-VL 训练流程

来源：arXiv **2511.21631**，《Qwen3-VL Technical Report》，v1 2025-11-26，v2 2025-11-27（API 核对）。官方博客是 JS 页面，没抓到，用 HF 模型卡和 config 补充。下面 p=PDF 页码。

**1. 预训练四段**（§3.1 Table 1，p4–5）
- S0 对齐：只训 merger，ViT 和 LLM 冻结；67B token；8K；数据是图文描述、视觉知识、OCR
- S1 多模态预训练：全参（ViT 也解冻）；约 1T；8K；VL+纯文本，含交错图文、grounding、VQA、STEM、少量视频
- S2 长上下文：全参；约 1T；32K；提高纯文本比例，加大视频和 agent 数据
- S3 超长：全参；100B；256K（262,144）；长视频、长文档
- 原文未写：数据配比、学习率、各阶段分辨率

**2. 视觉编码器**（§2，p3）：SigLIP-2 架构，从官方权重初始化，再用动态分辨率继续训练（2D-RoPE + 插值绝对位置）。默认 SigLIP2-SO-400M，2B/4B 改用 SigLIP2-Large(300M)，**8B 用 SO-400M**。config 交叉核对：8B 的 ViT 27 层/宽 1152，4B 24 层/1024。消融（§5.12.1，p24）：接 1.7B LLM 训 1.5T，InfoVQA 65.3→67.0，OmniBench 50.1→53.0。

**3. 后训练**（§4，p9–13）
- SFT：约 120 万条，1/3 纯文本；先 32K 训 1 个 epoch，再 256K 训 1 个 epoch（含最长 2 小时视频）；用 Qwen2.5-VL 过滤问题、用奖励模型过滤回答
- Instruct 和 Thinking 的分叉：SFT 数据分普通格式和 CoT 格式。Thinking 另有 Long-CoT 冷启动数据，图文和纯文本约 1:1；不看图也能答对的视觉数学题删掉（用 Qwen3-30B-nothink 判断）
- 蒸馏：**只用纯文本**调 LLM；先 off-policy（学教师输出），再 on-policy（学生自己生成，用 KL 对齐 logits）；教师是谁原文未写
- RL：推理 RL 约 30K 题，每题采 16 个回答，通过率 >90% 的题删掉，算法用 SAPO；通用 RL 管指令遵循和偏好，专门纠正"反直觉计数、钟表读时"这类错误先验，奖励由规则和 Qwen2.5-VL-72B/Qwen3 评判模型给
- 对照（Table 9/10，p23–24）：8B Instruct 与 Thinking 的 AIME-25 分别是 45.9 和 80.3；同样是 Instruct，Qwen3-8B 只有 20.9

**4. 数据构造**（§3.2，p5–9）：**大量用模型生成或重写**
- 图文描述：微调 Qwen2.5-VL-32B 重写描述，只对重写后的文本去重，按视觉聚类补稀疏区域（数量未写）
- 知识类：用 LLM 写的描述替换原 alt-text
- 交错图文：小模型分类，过滤广告；书籍用 Qwen2.5-VL-7B 解析，连续页拼到 256K
- OCR：3000 万条（专用 OCR 模型出伪标签，Qwen2.5-VL 修正，无人工），另合成 3000 万多语样本；文档 300 万 PDF + 400 万内部文档，由 Qwen2.5-VL-72B 识别
- Grounding：Qwen2.5-VL 提候选 → Grounding DINO 标框 → 过滤；坐标统一成 [0,1000]
- 视频：内部模型由短到长生成带时间戳的密集描述（数量未写）
- STEM：100 万点标注 + 200 万感知 VQA + 600 万图表描述；6000 万道习题；1200 万条长 CoT

**5. 结构设计的理由**
- Interleaved MRoPE（§2.1，p3）：分块切频率会让频谱不平衡，长视频变差；交错后每个轴都覆盖高低频。**没有专项消融**，只在 §5.9（p20）定性说过有帮助
- DeepStack（§2.2，p4）：取 ViT 3 个中间层，经各自的 merger 加到 LLM 前 3 层。消融（Table 12，p24；15B-A2B，200B token）：平均分 74.7→76.0，InfoVQA +2.3，DocVQA +1.6。8B 取第 [8,16,24] 层（config）
- 文本时间戳（§2.3，p4）：绑绝对时间的位置 id 在长视频里过大过稀，而且需要各种 fps 都有的训练数据；改成 `<3.0 seconds>`，训练时也混用"时:分:秒"格式。**没有消融**
- 大海捞针（p25）：30 分钟/256K 内 100%，YaRN 外推到 1M 是 99.5%

**6. Loss**：是否只在文本 token 上算，原文未写。摘要（p1）和引言（p2）各一句：从按样本平均改成"平方根归一化的按 token loss"，用来平衡文本和多模态数据。**公式、作用对象和消融都没写**。

## 二、作者早先 14 天讲义（D01–D14，全部是 Qwen3-VL-4B）

**编码**
- D07 shape trace：448² 图，pixel_values 784×1536（3×16²×2）→ merger 后 196×2560（4B 实测）
- D09 分辨率：0.25× 和 0.5× 都是 64 token，CER 0.58 对 0；到 900 token 准确率不再涨，prefill 41→101ms（实测）
- D09：输入 224² 被对齐成 256²（对齐到 32）（实测）；三条路径 196/980/1200 token（算术）
- D12 多图路径：2→32 帧，token 184→2164；8 帧均匀采样正好跳过事件（实测）
- D12 video 路径：fps=2、帧数 4–768，不给 metadata 时按 24fps 处理；2 帧 111 token，3–32 帧都是 168（只跑 processor）；时间戳插入方式来自源码
- D12：5 分钟视频约 58800 token（推导）

**注意力**
- D05 MRoPE：Qwen2-VL 分块 [16,24,24]，Qwen3-VL 交错 [24,20,20]；40×40 的图只占 40 个位置（源码/config）
- D05/D12：Qwen3-VL 的每个时间组按独立图片排位置，t 不编码时间（源码）
- D07 热力图：左半 70.3%，目标区 2.4%，峰值不在目标上（实测）
- D07 DeepStack：第 5/11/17 层加到 LLM 第 0–2 层（4B）
- D13：视觉塔占 prefill 37%；eager 和 sdpa 的 decode 差 11.9 倍；每千 token 耗时呈 U 形，最低点 L≈800；KV cache 每 token 144KB，算术和实测比值 1.00（H200 实测）

**训练**
- D08 玩具（195K 参数）：只训 projector 时纯文本 loss 变化 −0.0009，全参时纯文本 loss 升到 5.913，比随机猜还差
- D10：识别、方位、grounding 都是 100%，计数 58%（12 个场景）；是非题解析要先匹配否定词
- D11：三臂对照，合计捷径率 67%，拆开后正例 0%、负例 100%
- D05：视觉 token 位置的 label 设 −100（通用机制）；D06 数据分类和合成风险；D03 CLIP/SigLIP 随 batch 的扫描（玩具）

**示意 / 未验证 / 可能与 Qwen3-VL 不一致**
- 示意图：D01、D03、D04、D05、D14；只是算术：D02 的 P=14 表、D09、D12；数据集年份未验证：D06
- D02 用 P=14 举例，Qwen3-VL 实际 patch=16，一个 LLM token 对应 32×32 像素
- D04/D07 的 5/11/17 层是 4B，**8B 是 8/16/24**
- D13 写"注意力头 20、没 GQA 要乘 2.5"，但 config 是 32 头，应乘 4（20 是 2560÷128）
- D08 的通用流程写"视觉塔常冻"，Qwen3-VL 从 S1 起 ViT 就全参训练
- D05 写"只在文本上算 loss"，报告没写这一点；讲义也没提平方根归一化

**口播审核判定不能说的**
- 01–04：每层能独立替换；换更大 LLM 没技术含量；一个 token 就是一个概念；×16 不加限定；合并几乎零成本；0.738/0.069 是通用规律；对称损失是硬需求；数量和方位天生弱；LLaVA 初版就是 MLP；旁路完全不占上下文；15%/43%
- 05–07：没有看图模块；LLM 完全不知道输入是图；框架都能直接复用；1600 token、首字慢一个量级这类数字；4B 的数字不加限定；DeepStack 必然补回细节；2.4% 这类注意力百分比；去图后答案不变就下结论
- 08–11：解冻必然遗忘；token 数代表质量；拐点不取决于模型；动态分辨率不丢信息；计数必然串行；答案一致就是捷径；答案变了就是理解
- 12–14：采到事件就能识别；必须走多图路径；sdpa 天生慢；KV cache 是唯一瓶颈、唯一能算的量；减 token 不损质量；统一的优化排名；448²÷14² 当成进 LLM 的 token 数；"相差 32 倍"
