总结

token 数既是信息量也是成本：所以要给它设 上下限

1 个 token = 32×32 像素（上一页）。太大算不起，太小没东西可看，所以一张图的 token 数被卡在 64 ～ 16,384 之间，超出就整张等比缩放。
上限：16,384 个 token总像素 16,777,216，约等于 4096×4096
  • 边长翻倍 → token ×4 → ViT 两两打分 ×16（打分次数是序列长度的平方）
  • ViT 里还没合并，序列是 4 倍：65,536，两两打分要算约 43 亿个分数
  • 超过就等比缩小、向下取整
下限：64 个 token总像素 65,536，约等于 256×256
  • 图太小，切出来的 token 少到表达不了形状
  • 120×30 的标签按原尺寸只有 4×1 = 4 个 token
  • 低于下限就等比放大、向上取整
普通照片在范围内，只取整
→
1920×1080 → 1920×1088　2,040 token
很小的标签只有 4 个 token → 放大到下限
→
120×30 → 512×128　64 token
超大图4.7 万个 token → 缩小到上限
→
8000×6000 → 4704×3520　16,170 token
上下限取值来自 preprocessor_config 的 shortest_edge / longest_edge；官方未说明为何取这两个数。长宽比超过 200 直接报错
