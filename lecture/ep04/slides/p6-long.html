S2 / S3：先短后长，最后才把长度拉到 256K

8K 装不下长视频和几百页的文档。但序列越长越贵：注意力里每个 token 要和前面所有 token 打分，同样多的 token，256K 序列在注意力上的开销是 8K 的约 32 倍。所以大部分 token 在 8K 和 32K 上训，256K 只用 1000 亿 token 去适应长度。
能力在短序列上学，长度最后用少量数据适应
来源：Qwen3-VL 技术报告 arXiv 2511.21631 Table 1、§3.1 Stage 2/3（p5）、§3.2.7、§5.12.3；「先短后长」的理由是按注意力开销的推断，报告没写；32 倍只算注意力部分
